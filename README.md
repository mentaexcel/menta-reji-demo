# メンタレジ ── 自動化の練習用ダミーWebシステム

**API を持たない「昔ながらの社内Webシステム」を再現した、練習用のダミーサイトです。**

RPA（Power Automate Desktop など）やブラウザ自動化・AIエージェントの練習台として、
遠慮なく操作・スクレイピング・自動化してもらうために作りました。

実在の企業・店舗・人物とは一切関係ありません。実データは含みません。

## デモ

👉 **https://mentaexcel.github.io/menta-reji-demo/**

`index.html` をブラウザにドラッグ＆ドロップするだけでも動きます（サーバー不要・通信なし）。

## このシステムの一番の特徴：支店ごとにログインが分かれています

架空のカフェチェーン5支店のPOS（レジ）売上管理システムです。

- **支店ごとにログインIDとパスワードが違います**
- ログインすると、**その支店のデータだけ**が表示されます
- **全社合計を見る画面はありません。本部一括のIDもありません**
- 他支店の伝票番号を直接URLに入れても、エラーになって見られません

つまり **5支店分の数字を集めるには、5回ログインし直すしかありません。**
これがこのシステムを練習台として作った理由です。

## データについて

- 期間：2026年8月1日〜8月31日（5支店合計で伝票 約6,600枚）
- 支店：北海道・東京・大阪・神奈川・沖縄（すべて架空）
- 商品14品目、支払方法4種、レジ担当者は支店ごとに4名（すべて架空）
- 返品伝票は**数量・金額をマイナス**で計上しています（客数にはカウントしません）
- **`assets/data.js` の固定シードでその場生成**しています。データベースも通信もありません。
  何度開いても、誰が開いても、同じ数字が出ます。

### 数字は必ず突き合わせられます

切り口が違うだけで、同じ伝票を足しているので、次の5つは**必ず同じ金額になります**。
自動化で取った数字が正しいかを検算できるように、わざとそう作ってあります。

1. 売上明細の金額列を全部足した額
2. 日別集計の「月計」
3. 商品別売上の「合計」
4. スタッフ別の合計
5. 日別集計の支払方法4種（現金・クレジット・QR決済・電子マネー）の合計

## わざと残してある「自動化したくなるポイント」

練習台として役に立つように、古い業務システムにありがちな不便さを意図的に残しています。

1. **支店ごとにログインが分かれている** ── 全社の数字を出すには5回ログインし直すループが必要
2. **全社合計の画面が無い** ── 横断で見る手段がそもそも用意されていない
3. **CSV出力ができない** ── 画面から数字を取るしかない
4. **グラフが1つもない** ── 集計は自分で外に出す必要がある
5. **ページ送りが必要** ── 全件取得はループ必須
6. **1回の検索で10ページ（表示件数×10件）までしか出せない** ── 全件を取るには売上日を区切って何回も検索する必要がある
7. **列のソートができない** ── 見出しをクリックしても反応しない
8. **日付が手入力** ── カレンダーが出ない
9. **画面幅が固定（950px）** ── スマホで見られない
10. **前月比・前年比が出ない**
11. **APIが無い** ── これがこのシステムの本質。裏口が無いので画面を操作するしかない

## HTMLの構造は固定してあります（データ抽出が壊れないように）

古い画面の見た目はそのままですが、**中身のHTMLは支店やページが変わっても同じ形**になるように作ってあります。
Power Automate Desktop の「Web データ抽出」やスクレイピングで、
**支店を切り替えたら取れなくなる、という事故が起きないようにするため**です。

### 一覧テーブル

- 一覧は必ず `<table id="list">`。見出しは `<thead>`、データは `<tbody>`、合計は `<tfoot>` に分かれています
- **データ行 `<tbody> <tr>` には class を一切付けていません。** 全支店・全ページ・返品行もまったく同じ形です
- 返品行も**HTMLはまったく同じ**です。返品かどうかは「区分」列の文字と、金額のマイナス表示で判別してください
- セルの class は**列ごとに固定**です（下表）
- 縞模様と返品の赤字は **CSSだけ**で表現しています（`:nth-child` と `:has`）。HTMLは変わりません

売上明細（sales.html）の列：

| 位置 | class | 内容 |
|---|---|---|
| 1 | `col-no` | 通し番号 |
| 2 | `col-id` | 伝票番号 |
| 3 | `col-store` | 店舗名 |
| 4 | `col-date` | 売上日 |
| 5 | `col-time` | 時刻 |
| 6 | `col-reg` | レジ |
| 7 | `col-staff` | 担当者 |
| 8 | `col-item` | 商品 |
| 9 | `col-qty` | 点数 |
| 10 | `col-pay` | 支払方法 |
| 11 | `col-amount` | 金額（税込） |
| 12 | `col-status` | 区分（通常／返品） |
| 13 | `col-link` | 詳細へのリンク |

`col-store` は**ログイン中の支店名**が入ります。5支店ぶんを1つの表にまとめたとき、
どの行がどの支店のものか分かるように付けてあります。

日別集計は `col-date` `col-dow` `col-count` `col-cust` `col-amount` `col-avg` `col-cash` `col-credit` `col-qr` `col-emoney` `col-return`、
商品別は `col-rank` `col-code` `col-name` `col-cat` `col-price` `col-qty` `col-amount` `col-share`、
スタッフ別は `col-rank` `col-staff` `col-count` `col-cust` `col-amount` `col-avg` `col-perslip` です。

### ページ送り

ページャーは常に **「先頭・前へ・ページ番号・次へ・最終」の5ブロック**を出します。
使えないときは `<a>` ではなく `<span class="pgoff">` になるだけで、**並びは変わりません。**

| 要素 | id |
|---|---|
| «先頭 | `pgFirst` |
| 前へ | `pgPrev` |
| 次へ | `pgNext` |
| 最終» | `pgLast` |

**送りボタンの `href` にはページ番号を入れていません。** 飛び先はクリック時に決まります。
そのため「次へ」のHTMLは、**どの支店でも、何ページ目でも、まったく同じ1行**です。

```html
<a id="pgNext" href="#" onclick="return goNext();">次へ</a>
```

最後のページだけ `<a>` が `<span class="pgoff">` に変わって `#pgNext` が消えるので、
**「`#pgNext` が在るあいだ繰り返す」でループの終了判定ができます。**
総ページ数は検索結果の行に「全 n ページ中 m ページ目」と文字で出しています。

### 行数について

表示件数50件のとき、どの支店も10ページ分（各50行）が埋まります。
売上日を絞り込んだ場合だけ、最終ページの行数が50未満になります。

## 想定している使い方

- Power Automate Desktop / RPA の練習
  （Excelの一覧からIDとパスワードを1行ずつ読む → ログイン → 数字を取る → 書き戻す → ログアウト → 次の支店）
- ブラウザ自動化（Playwright・Selenium）の練習台
- AIエージェントにWeb操作をさせる実験
- 「APIがあるシステム」と「無いシステム」で自動化の作り方がどう変わるかの比較

ログイン状態は `sessionStorage` に保持しています。タブを閉じるかログアウトすると解除されます。
